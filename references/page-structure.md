# Adaptive Page Structure

Use only sections that add value.

## Recommended baseline

01 Hero
- product/launch name
- distinctive official phrase when appropriate
- concise analytical intro

02 Product positioning
- models and roles
- one visual hierarchy, not a spec dump

03 Imaging comparison
- normalized focal length/aperture/video differences
- table or compact comparison only when useful

04 Official imaging upgrades
- optics/hardware
- computational photography
- video/audio/workflow
- front camera/interaction

05 Interactive feature explorer
Suggested tabs:
A Photography / optics
B Pro video / audio
C Form-factor imaging or computational features

If no meaningful C exists, use two tabs. Never force three.

06 Creator & media observation
- newest full reviews first
- older hands-on demoted
- comprehensive summaries
- original links

07 Cross-source synthesis
- what changed after full reviews
- agreements
- disagreements/test conditions
- third-party technical interpretation

08 Industry implications
Possible lenses:
- optics;
- sensors;
- computational imaging;
- video workflow;
- audio;
- interaction;
- competitor/Android direction.

09 Sources
Simple numbered vertical list.

## Optional sections

- sample gallery: only with licensed/official/reviewer-permitted images and provenance;
- firmware update note;
- price/availability if it materially affects interpretation;
- historical comparison to previous generation.

## Copy rules

Do not write:
- “本页面整理……”
- “我们核实了……”
- “以下内容来自……”
- implementation notes;
- self-congratulatory design descriptions.

Write the analysis itself.
